# ДЫМ — техническое задание

Демо-лендинг вымышленной smash-бургерной в Батуми. Кейс для портфолио **Mr. Web** (разработка лендингов на заказ).

## Цель

Показать потенциальным заказчикам, что лендинг одновременно **продаёт** (понятный оффер, путь к заказу, соцдоказательства) и **запоминается** (2–3 вау-момента).

**Аудитория портфолио:** владельцы малого бизнеса (общепит, локальные сервисы) и заказчики с фриланс-бирж. Смотрят чаще с телефона.

## Бренд

- **Название:** ДЫМ — «smash-бургеры на открытом огне».
- **Город:** Батуми, адрес вымышленный.
- **Характер:** дерзкий крафт. Тёмный фон, огонь, дым, крупная жирная типографика, тон текстов — с юмором и наглостью. Слоган одного из бургеров: «Жир не враг».
- **Палитра** (токены в `src/styles/global.css`, стандартная палитра Tailwind отключена):

  | Токен | Hex | Роль |
  |---|---|---|
  | `soot` — сажа | `#17110D` | фон |
  | `iron` — чугун | `#2A1F19` | поверхности, карточки |
  | `ember` — жар | `#FF5B1F` | главный акцент, CTA |
  | `cheddar` — чеддер | `#F5B32B` | второй акцент, цены, бейджи, фокус |
  | `brioche` — бриошь | `#F4DDB0` | основной текст (14:1 на `soot`) |
  | `smoke` — дым | `#A39486` | вторичный текст (6.4:1 на `soot`) |

- **Шрифты** (self-hosted через Fontsource):
  - **Science Gothic** (variable, оси `wdth` 50–200 % и `wght`) — заголовки. Ось ширины — фирменный приём: «smash» = буквы расплющиваются как котлета под прессом.
  - **Golos Text** (variable) — текст и интерфейс.
- **Фирменный вау-приём hero:** при загрузке слово ДЫМ появляется узким (`font-stretch: 50%`), затем его «придавливает» — оно расплющивается и расползается на всю ширину (`200%`) с отскоком. Чистый CSS, без JS.
- **Язык:** только русский.
- **Валюта:** лари (₾).

- 3 сайда, 3 напитка.
- 1–2 комбо (собираются из существующих фото, отдельные картинки не нужны).

## Структура страницы

1. **Hero** — оффер, фирменный бургер, CTA «Заказать».
2. **Фишки = взрыв-схема** — «Классика дыма» разобрана на слои, у каждого слоя подпись с фишкой (бриошь из пекарни, свой маринад, фарш каждое утро и smash на чугуне, соус). Так два блока слились в один, а фишки показаны на самом продукте.
3. **Меню** — табы «Бургеры / Закуски / Напитки», карточки с кнопкой «В корзину». На мобилке карточка горизонтальная (фото слева).
4. **Комбо / акция** — например, «второй бургер −50% по вторникам».
5. **Отзывы** — 3–4 вымышленных, с именами и аватарами.
6. **Доставка** — зоны по Батуми на живой карте, время, минимальная сумма, бесплатная доставка от X ₾.
7. **FAQ** — 4–5 вопросов.
8. **Футер** — адрес, часы, навигация, плашка «Демо-проект. Дизайн и разработка — Mr. Web» со ссылкой на Instagram Mr. Web (ссылка — TODO, пока заглушка).

Плюс: липкая корзина и выезжающая панель оформления заказа.

## Заказ

- Корзина хранится в `localStorage` и синхронизируется между вкладками.
- «Жирный вторник» считается автоматически по времени Батуми: −50 % на самый дешёвый бургер, если бургеров в заказе хотя бы два (сет не участвует). Для демонстрации в любой день — `?tuesday=1` в адресе.
- Минимальный заказ 15 ₾ блокирует оформление; при доставке показывается, сколько добавить до бесплатной.
- Оформление: переключатель «Доставка / Самовывоз», имя, телефон с маской `+995`, адрес (только для доставки), время («как можно скорее» / ко времени), оплата (наличные / карта курьеру), комментарий.
- Никакой реальной отправки. После «отправки» — экран «Заказ #NNNN принят, привезём к HH:MM» и мелкая пометка, что это демо.

## Карта доставки

Leaflet + стандартные тайлы OpenStreetMap, затемнённые CSS-фильтром под палитру (CARTO и Stadia требуют API-ключ). Зоны — приблизительные полигоны вдоль побережья. Leaflet и тайлы грузятся только при приближении к блоку (IntersectionObserver), чтобы не просел Lighthouse. На телефоне карта не перехватывает прокрутку страницы: двигается щипком.

## Вау-моменты

1. **Взрыв-схема** (блок «Фишки», не hero) — при скролле собранный бургер разлетается на слои с подписями. Нужны отдельные PNG слоёв на прозрачном фоне.
2. **Полёт в корзину** — при добавлении картинка летит по дуге в иконку корзины, счётчик подпрыгивает.
3. **Кинетическая типографика** — огромные буквы, бегущие строки, реакция на скролл.

Отложено как возможное расширение: конструктор бургера.

Все анимации уважают `prefers-reduced-motion`.

## Фото

Генерирует Рома в ChatGPT по промптам из [`prompts.md`](../prompts.md). Единый стиль: тёмный фон, драматичный свет, дым, крупный план. До появления фото вёрстка идёт на заглушках; готовые картинки оптимизируются в WebP/AVIF через `astro:assets`.

## Стек и инфраструктура

- Astro + Tailwind CSS 4, статическая сборка.
- Публичный репозиторий на GitHub.
- Хостинг — Vercel, превью на каждый PR. Прод: https://dym-batumi-landing.vercel.app (превью PR закрыты Vercel Deployment Protection — открываются только под аккаунтом Vercel).

## Критерии готовности

- Адаптив от 360px до десктопа, mobile-first.
- Lighthouse (mobile) ≥ 95 по Performance, Accessibility, Best Practices, SEO.
- Доступность: контраст, видимый фокус, `alt`, работа с клавиатуры, `prefers-reduced-motion`.
- SEO-мета, OG-картинка (превью в Telegram), favicon.
- README-кейс: задача, решения, стек, скриншоты.

## Этапы

Каждый этап — отдельная ветка и PR в `main`, проверка по превью Vercel.

1. **Каркас** — Astro + Tailwind, репозиторий, деплой, `docs/spec.md`, `prompts.md`.
2. **Дизайн-система и hero** — палитра, шрифты, первый экран. Утверждение стиля.
3. **Секции** — все блоки на заглушках, адаптив.
4. **Заказ** — корзина, оформление, карта.
5. **Финал** — вау-анимации, реальные фото, полировка, Lighthouse, README-кейс.

## Технический долг на этап 5

- Урезать Science Gothic до нужных глифов (`pyftsubset` с сохранением осей): сейчас латинский сабсет весит 95 КБ и грузится из-за цифр и слова «Smash».
- Заменить заглушки на фото через `astro:assets`: `BurgerPlaceholder` → `hero-burger`, `BurgerLayer` → `layer-*`, `FoodPlaceholder` → позиции меню, инициалы в отзывах → `avatar-*`.
- Соцсети у вымышленной бургерной не выводим — ссылки в никуда в портфолио выглядят неряшливо.
